## Destination

A build-ready v1 spec for 小芽分帳 (short form 小芽), served at `split.rickchen.si`: stack, domain model, data model, API contract and screens, with nothing left to decide before implementation planning starts. This map plans; it does not build the app.

## Notes

- Tracker is local markdown. Tickets are files in `tickets/`; a ticket is open or closed by its `status:` front matter, claimed by its `assignee:`, and blocked by the files in `blocked_by:`. The frontier is every open, unassigned ticket whose blockers are all closed.
- Standing preference: build and test locally first and deploy last. Local work needs no Cloudflare, LINE or Google account, so the console checklist gates only the integration and deploy steps, not the start of building. The delivery order in the final spec is written that way.
- Standing preference: all-free infrastructure; assume no paid plan anywhere (Cloudflare, LINE, Google, FX source). Where a decision needs more than a free tier gives, say so and look for the cheapest change that stays free.
- Settled: Cloudflare edge only (Pages or Workers assets, Workers + Hono, D1 + Drizzle, KV for caches, `jose` for tokens); Google sign-in on Chrome, LINE LIFF and Bot on mobile; one Group concept (Running Tab or Trip); one User with many Identities; integer minor-unit money; currency chosen per Expense; Settlement currency chosen per Group; v1 supports TWD and USD only (the model stays currency-generic, so more currencies are added later without redesign); D1 batch writes and a D1 idempotency key (to be confirmed by research); v1 is zh-TW only; Invites are LINE-shared links; the product is named 小芽分帳 (short 小芽, sprout mascot with a friendly voice, no chat persona) and lives at `split.rickchen.si`.
- Profile pictures: only the provider's picture URL and name are stored and refreshed at each sign-in, with an initial-letter fallback and the most recent provider winning; no avatar upload in v1 (noted on the privacy ticket).
- Domain terms live in `GLOSSARY.md` at the repo root; consult it and keep it current.
- Designs: `docs/split.pen` (31 frames, readable through the Pencil MCP). `split.pen` is the starting point, not the contract; a decision overrides a frame and the map records the divergence.
- Skills every session should call: `grilling` and `domain-modeling` for HITL tickets, `research` for research tickets.

- [Research Cloudflare hosting for the SPA and Workers](tickets/03-research-cloudflare-hosting.md): serve the SPA as Workers static assets with Hono in one Worker; `waitUntil` is best-effort only, so critical writes go to D1 first (its note to "plan for Workers Paid" is superseded by the all-free preference; see the free-tier research).
- [Research D1 atomicity and KV consistency](tickets/04-research-d1-and-kv-guarantees.md): one `batch()` per Expense with a UNIQUE idempotency key in D1; KV is not an idempotency guard.
- [Research exchange rate sources](tickets/06-research-fx-rate-sources.md): Frankfurter as primary (covers TWD, no key, free for commercial use), ExchangeRate-API as fallback; ECB lacks TWD.
- [Research debt simplification algorithms](tickets/07-research-debt-simplification.md): greedy is not minimal (minimising is NP-hard, bound is N-1); use an exact search for about 20 or fewer non-zero balances, greedy otherwise, and label "fewest payments" only when the exact path ran.
- [Research LINE LIFF, share and Bot constraints](tickets/05-research-line-platform.md): one provider for LIFF and Bot, verify the LIFF ID token locally (ES256 via JWKS), HMAC webhook with a 2s reply and `waitUntil`, URI-only Flex invites with a copy-link fallback; silent login and shareTargetPicker contexts unconfirmed.
- [Decide the product name](tickets/01-decide-product-name.md): 小芽分帳 (short 小芽) everywhere in v1, 一起分 dropped; web app at `split.rickchen.si`, handle `split`.
- [Export design screens to docs/screens](tickets/02-export-design-screens.md): all 31 frames exported as PNGs with an index in `docs/screens/`; the currency picker still shows JPY and EUR against the TWD and USD v1 scope.
- [Decide money storage and split rules](tickets/08-decide-money-and-split-rules.md): TWD in whole dollars, USD in cents; split methods are equal, exact amounts and shares (no percentage split); leftover units go one each starting with the payer; default split is all Members; limit 99,999,999 units, no negative Expenses.
- [Decide the exchange rate policy](tickets/11-decide-fx-rate-policy.md): Frankfurter (ExchangeRate-API fallback) fetched by the Worker and cached in a D1 table; rate stored per Expense with its date and an edited flag; saving is never blocked; the Expense's own date, else the last earlier day; four decimals; Settlement currency fixed after the first Expense.
- [Decide identity linking and sessions](tickets/09-decide-identity-and-session.md): first sign-in creates a User; linking only while signed in, no email merge and no User merging in v1; always keep one Identity; 1-hour Bearer access token plus a 30-day rotating refresh cookie hashed in D1; only `sub`, name and picture stored.
- [Research whether free tiers carry v1](tickets/19-research-free-tier-fit.md): the free tiers carry v1 except two things: the exact settlement search is too slow for the 10 ms Workers CPU limit (run it in the browser or cap it at 12 to 14 balances), and LINE push is capped at 200 messages a month (use replies and share links only).
- [Decide invites and membership rules](tickets/10-decide-invite-and-membership.md): random 7-day invite link, regenerate to revoke, 30 Members max; sign-in then instant join as 成員; admins and members with creator-only Expense edits; leave or removal only at zero balance; admin-only permanent hard delete of a Group.
- [Decide the settlement flow](tickets/12-decide-settlement-flow.md): Worker returns balances, the browser computes the plan (exact search up to 20 balances, else greedy; labelled honestly); the receiver confirms each payment, partial payments allowed, undoable, Expenses stay editable with a warning; Settlement currency only; no automatic reminders.
- [Decide the Trip module scope for v1](tickets/13-decide-trip-module-scope.md): destination, dates, notes and day stops (name, time, category, text location, note) only; no map or place search, no drag order; Expenses optionally link to a stop; any Member edits stops, admins edit the trip; trip module can be switched off without deleting data; default Expense currency per Group.
- [Decide the LINE Bot scope for v1](tickets/14-decide-line-bot-v1-scope.md): chat entry stays out; one static six-button Rich Menu linking into the LIFF app; the Bot only replies (welcome, help, menu pointer) and never pushes; invites and summaries are user-shared Flex cards; Bot not added to group chats; follow, message and help-postback webhook only.
- [Decide the data model](tickets/15-decide-data-model.md): ten tables (user, identity, session, group, member, invite, expense, expense_split, settlement, stop, fx_rate) with random IDs, stored per-member Balances updated in the same batch, local-text dates, soft-undone Settlements, hard-deleted Expenses and Groups, a delete-account rule, and caps for the free plan.
- [Decide the API contract](tickets/16-decide-api-contract.md): typed Hono JSON API under `/api/v1` with shared Zod schemas, one error shape with stable codes (client maps to zh-TW), idempotency key and `updated_at` conflict checks, cursor lists, one origin with no CORS; adds a pending "我已付款" Settlement the receiver confirms.
- [Reconcile the designs with the decisions](tickets/17-reconcile-designs-with-decisions.md): per-Group statistics only; bottom bar 首頁, 群組, +, 統計, 設定 with no LINE Bot tab; no notification or user-level default-currency settings; home total per currency; one responsive web app; `split.pen` is not edited here; full list of changes in `docs/design-changes.md`.
- [Research receipt images and LIFF messaging on free plans](tickets/24-research-receipt-images-and-liff-messaging.md): receipt photos fit a private R2 bucket proxied through the Worker if R2 needs no card (unconfirmed; else small D1 images); `liff.sendMessages` works from a chat-launched LIFF with `chat_message.write` and is probably outside the message quota (unconfirmed), with `shareTargetPicker` as the fallback.
- [Decide the testing strategy](tickets/22-decide-testing-strategy.md): one pure shared money package with unit and property tests of the sum invariants, in-memory D1 tests of batch rollback, idempotency and caps, no-network API and sign-in tests, three Playwright flows with a test-only login that must 404 in production, and a pull-request gate with gitleaks and "every data-model rule has a test".
- [Decide the add-Expense form features](tickets/23-decide-add-expense-form-features.md): tabs 花費 and 轉帳 only (no 收入); date and optional time; typed converted amount with the rate derived; several payers; on-device calculator; one receipt photo if R2 needs no card; optional send to the current LINE chat; data model and API amended.
- [Decide the frontend stack](tickets/20-decide-frontend-stack.md): React and Vite in strict TypeScript under 200 KB gzipped first load; React Router, TanStack Query v5 and Hono's typed client; Tailwind v4 with design-token variables and a few Radix parts; React Hook Form on the shared Zod schemas; hand-written calculator parser; LIFF from npm with a LINE-or-browser sign-in split; exact payment search in a Web Worker; one zh-TW message catalog and no PWA.

## Out of scope

- Direct linking of LINE group chats to app Groups: ruled out of v1; invitations use LIFF share picker links.

- Currencies other than TWD and USD in v1 (JPY, THB, EUR and the rest): the TWD and USD pair ships first; adding a currency is a later change, not a redesign.
- Japanese and Thai localization and other UI languages: v1 is zh-TW only; returns as a fresh effort.
- Expense entry by chatting with the LINE Bot: v1 Bot is Rich Menu and notifications only.
- Payments or bank transfers, including QR payment methods: settlement is recorded, not executed.
- Map or place search, routing, weather, bookings, photos, per-stop budgets, offline mode and itinerary export in the Trip module: not free or not needed for v1.
- Writing any application code: this map ends at the spec.
