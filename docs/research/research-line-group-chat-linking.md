# Research: linking an app Group to a LINE group chat

All sources read on 2026-10-28 (LINE Developers docs, English). "Unconfirmed" marks anything not stated in a primary page I could read. Some fetches were summarised by a tool and the pages were truncated, so quotes are as reported by the fetch tool, not copied by hand.

## Verdict

**Does not fit** as a direct link (opened from this chat means this chat). LIFF no longer exposes the group ID, so the LIFF app cannot know which LINE group chat it was opened from. The only ID source is a Bot webhook, which needs the Bot inside the group, which v1 rules out.

Keep the current Invite link design. Optional cheap addition at the end.

## 1. liff.getContext() in a group or multi-person chat

- `type` is still returned: `utou`, `group`, `room`, `external`, or `none`. `userId` is returned for these types (may be null for `external`). `viewType` and `scope` are also returned. Source: https://developers.line.biz/en/reference/liff/ (read 2026-10-28).
- `groupId`, `roomId` and `utouId` are discontinued. The reference says LINE has "discontinued providing company internal identifiers of chat rooms to LIFF apps". Same source and date.
- Timeline: planned in the notice dated 2022-12-27 ("Plans to discontinue providing company internal identifiers of chat rooms to LIFF apps", https://developers.line.biz/en/news/2022/12/27/liff-spec-change/, listed on https://developers.line.biz/en/news/2022/, read 2026-10-28; the notice body itself did not load, only the listing summary). A later notice titled "...will be discontinued on February 6, 2023" is at https://developers.line.biz/en/news/21 but its body did not load; the date comes from a web search snippet. Treat the 2023-02-06 date as unconfirmed.
- LINE's own suggested replacements (from the 2022 listing summary): issue your own unique ID per chat and put it in the LIFF URL, or take the group or room ID from Messaging API webhook events.
- Because the ID is gone, the question of whether the Official Account must be a member, or whether scope or launch method changes the ID, does not arise for `getContext()`. The page documents no such condition. Unconfirmed that any condition ever applied.
- Stability of the ID: the group ID is "generated by the LINE Platform to identify group chats" (FAQ, https://developers.line.biz/en/faq/, read 2026-10-28). The FAQ does not say whether it changes. Stability is unconfirmed. Multi-person chats were merged into group chats from LINE 10.17.0, and old multi-person chats still work (https://developers.line.biz/en/docs/messaging-api/group-chats/, read 2026-10-28), so a `room` ID and `group` ID can both exist for legacy chats.
- Caveat: a 2026-08-06 LINE tips article says "chat room information can be retrieved via liff.getContext()" (https://developers.line.biz/en/tips/2026/08/06/between-liff-browser-and-external-browser/, read 2026-10-28). That is consistent with `type` still being returned, but it does not say the IDs return. The reference page is the authority.
- Related: `type` is also returned after transitioning between LIFF apps (reference page).

## 2. What the Bot can and cannot do in a group chat (free plan)

- Joining is opt-in: the console switch "Allow bot to join group chats" is off by default. Only one Official Account can be in a group chat at a time. Source: https://developers.line.biz/en/docs/messaging-api/group-chats/.
- Events: join (bot added; has `replyToken`), leave (bot removed; no `replyToken`), memberJoined (has `replyToken`), memberLeft (no `replyToken`). Sources: https://developers.line.biz/en/docs/messaging-api/receiving-messages/ and https://developers.line.biz/en/reference/messaging-api/ (read 2026-10-28). Leave and memberLeft carry only the `source` and no way to reply.
- Message events from a group include `source.groupId` and `source.userId`. `userId` is only present for LINE iOS and Android users, and is omitted if the user has not consented to profile access (https://developers.line.biz/en/docs/messaging-api/getting-user-ids/). So the Bot sees the sender of each event only.
- Member list: the "Get group chat member user IDs" endpoint (`GET /v2/bot/group/{groupId}/members/ids`) is "available only for verified or premium accounts" (getting-user-ids page). A free, unverified account cannot list members. Whether the account here is verified is unconfirmed. Member count and member profile endpoints exist (group-chats page), but their account-tier limits did not load. Unconfirmed.
- You cannot list which group chats the account is in (FAQ, https://developers.line.biz/en/faq/).
- Replies: allowed in groups like one-on-one chats (group-chats page). Reply messages are not counted toward the plan's monthly message total; push, multicast, broadcast and narrowcast are (https://developers.line.biz/en/docs/messaging-api/pricing/, read 2026-10-28). Free plan figure there: up to 200 messages a month (Japan; the page says other regions differ). Whether the owner's region matches is unconfirmed. Reply token validity time did not load. Unconfirmed.
- Push into a group counts per recipient: one push of four messages to a five-person chat counts as five (pricing and sending-messages pages). A push to a group is therefore expensive on a 200 quota. Multicast to groups is not allowed.
- Mentions: a user mentioning the Bot appears in `mention.mentionees[]` with `type: "user"`, `isSelf: true`; "@All" appears as type `all` (receiving-messages and reference pages). The Bot can read mentions, so a mention-triggered reply works. Whether the Bot can mention others in replies was not checked. Unconfirmed.

## 3. Ways into the LIFF app from inside a group chat

- A Rich Menu: not shown in group chats. Unconfirmed on the pages read (the claim in the task is plausible but I did not find a statement of it).
- A user sends the LIFF URL (`https://liff.line.me/{liffId}`) in a chat and others tap it (https://developers.line.biz/en/docs/liff/opening-liff-app/). This works from a group. LINE does not guarantee whether it opens in the LIFF browser or an external browser (same page).
- `liff.shareTargetPicker()` can send up to 5 messages, including Flex, to groups, friends and chats. Flex and template messages support only URI actions (https://developers.line.biz/en/reference/liff/). That is the existing Invite flow. OpenChat is not included. Requires login and the console option.
- The LIFF URL can carry extra path or query data, delivered in the `liff.state` parameter (opening-liff-app page). So the Invite link can carry an app invite token. This is what LINE recommends as the replacement for the lost group ID.
- Inside the LIFF browser launched from a group, `type` is `group`, but nothing identifies which group.

## 4. Security of "opened from this LINE group chat" as proof of membership

- Without a group ID there is nothing to match. Even `type: "group"` says only "some group".
- `getContext()` is client-side. The docs do not describe it as verified and warn that mishandled user data leaves a LIFF app "vulnerable to spoofing and other types of attacks". The server must verify the ID token or access token with LINE, not trust profile values sent by the client (https://developers.line.biz/en/docs/liff/using-user-profile/ and https://developers.line.biz/en/docs/liff/developing-liff-apps/, read 2026-10-28). Those tokens prove user identity, not chat membership.
- The LIFF URL is a plain HTTPS link; anyone who has it can open it in a browser, and in an external browser `type` is `external`. The docs do not say a spoofed context is impossible. A forged `getContext()` result is trivially possible because the endpoint page is code the user's browser runs. Treat as spoofable.
- Leaving the chat: the LIFF app gets no webhook. Only the Bot gets `memberLeft`, and only if it is in the chat. A person who leaves the chat keeps the link and any server-side membership you granted. Revocation would need Bot events, so it is not possible in v1.
- A leaked link is the same risk with either design, so keep invite tokens secret, expiring, and revocable by the app Group owner.

## Cheapest design that stays free

1. Keep v1 as decided: no Bot in the chat, Invite link via `shareTargetPicker`, token in the `liff.state` data, server verifies the LINE ID token and the invite token.
2. Add no automatic "LINE group = app Group" link. If the owner wants a hint in the UI, store a manual label only.
3. If a real link is wanted later (change required): add the Bot to the chat (turn on "Allow bot to join group chats"), and have a member send a one-time code in the chat (for example "/link ABC123" or an @mention). The webhook gives `groupId` plus the sender's `userId`, and the reply is free. Store `groupId` against the app Group. Do not use push. Join and memberLeft events can then keep a mapping current, but only if the Bot stays. Open items to check first: the account's verified status (needed for member lists), and reply token validity.
